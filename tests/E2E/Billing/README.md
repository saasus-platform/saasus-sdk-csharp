# Billing API E2E tests

These tests reproduce the Stripe connection lifecycle used by the Go and PHP SDKs:

1. Remove any existing Stripe connection.
2. Verify that Stripe is not registered.
3. Register a Stripe test-mode secret key.
4. Verify that Stripe is registered.
5. Delete the connection and verify the final unregistered state.

The lifecycle is executed with all four method styles generated by the C# SDK:
synchronous, synchronous `WithHttpInfo`, asynchronous, and asynchronous
`WithHttpInfo`. This covers all 12 public Billing Stripe methods.

The test changes live Billing API state and therefore runs only when explicitly enabled:

```bash
SAASUS_E2E=true \
SAASUS_SAAS_ID=... \
SAASUS_API_KEY=... \
SAASUS_SECRET_KEY=... \
STRIPE_SECRET_KEY=sk_test_... \
dotnet test tests/SaaSusSdk.Tests.csproj \
  --filter 'Category=E2E'
```

Use a dedicated SaaSus environment and a Stripe test-mode key. `SAASUS_API_URL_BASE`
can override the default `https://api.saasus.io` host. Setup and cleanup delete an
existing Stripe connection, including after a failed step.

## Snapshot tests

Billing snapshots have a dedicated test and four modes. Capture/full call the live API;
compare/report are offline and require only stored tag files.

```bash
# Capture a versioned baseline
SAASUS_E2E=true E2E_SNAPSHOT_MODE=capture E2E_SNAPSHOT_TAG=billing-v1 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&Module=billing'

# Compare two saved tags without credentials
E2E_SNAPSHOT_MODE=compare E2E_SNAPSHOT_COMPARISON_MODE=manual \
E2E_SNAPSHOT_OLD_TAG=billing-v1 E2E_SNAPSHOT_NEW_TAG=billing-v2 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&Module=billing'

# Generate JSON and HTML reports without calling the API
E2E_SNAPSHOT_MODE=report E2E_SNAPSHOT_COMPARISON_MODE=manual \
E2E_SNAPSHOT_OLD_TAG=billing-v1 E2E_SNAPSHOT_NEW_TAG=billing-v2 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&Module=billing'

# Capture, validate, compare with a previous tag, and report
SAASUS_E2E=true E2E_SNAPSHOT_MODE=full E2E_SNAPSHOT_TAG=billing-v2 \
E2E_SNAPSHOT_OLD_TAG=billing-v1 E2E_SNAPSHOT_NEW_TAG=billing-v2 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&Module=billing'
```

Artifacts use the Go/PHP layout beneath `tests/E2E/Snapshots/billing/`:

```text
story_snapshots/tags/story_snapshot_<tag>_<story>.json
story_validations/story_validation_<story>_<tag>.json
story_comparisons/<old>_vs_<new>/<story>.json
story_reports/<old>_vs_<new>/<story>.json
story_reports/<old>_vs_<new>/<story>.html
```

Only the two newest validation artifacts per story are kept; each one embeds a
`comparison` block naming the previous file and listing findings that appeared or were
resolved since then.

Additional options:

- `E2E_SNAPSHOT_CAPTURE_LEVEL`: `FULL`, `STORY`, `STEP`, or `RESPONSE`
- `E2E_SNAPSHOT_STORIES`: comma-separated story name or slug filters
- `E2E_SNAPSHOT_OUTPUT`: output root override
- `E2E_SNAPSHOT_MODULE`: module directory name (default `billing`)
- `E2E_SNAPSHOT_FILE_NAME_FORMAT`: snapshot file name template
- `E2E_SNAPSHOT_COMPARISON_MODE`: `release`, `manual`, or `skip`
- `E2E_SNAPSHOT_VERBOSE=true`: print resolved settings
- `E2E_SNAPSHOT_OVERWRITE=true`: explicitly replace the same tag
- `E2E_SNAPSHOT_FAIL_ON_BREAKING=false`: report breaking changes without failing
- `E2E_SNAPSHOT_DYNAMIC_FIELDS`: extra field names normalised to `[DYNAMIC]`
- `E2E_SNAPSHOT_DEFAULT_DYNAMIC_FIELDS=false`: disable the built-in dynamic field list
- `E2E_SNAPSHOT_HISTORY_LIMIT`: validation artifacts retained per story (default `2`)
- `SDK_VERSION` / `E2E_TEST_ENVIRONMENT`: values recorded in `metadata`

Capture refuses failed stories and rejects dry-run results. Existing same-tag snapshots
are not replaced unless overwrite is explicitly enabled. Two stories whose names
normalise to the same slug are rejected rather than silently overwriting each other.

The command-line wrapper maps flags to the same configuration:

```bash
bash tests/snapshot.sh --mode compare --comparison-mode manual \
  --old-tag billing-v1 --new-tag billing-v2 --verbose
bash tests/snapshot.sh --help
```

A JSON configuration file can replace the environment variables; see
[`tests/E2E/snapshot-config.example.json`](../snapshot-config.example.json), which also
shows how to override per-rule validation severities.

## Re-capturing a baseline

Snapshots are always produced by a live run, never converted from older artifacts. To
refresh an existing tag in place, pass the same tag and allow overwriting:

```bash
SAASUS_E2E=true E2E_SNAPSHOT_MODE=capture \
E2E_SNAPSHOT_TAG=v1.0.0-8-gbcd96cd E2E_SNAPSHOT_OVERWRITE=true \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&Module=billing'
```

or with the wrapper:

```bash
bash tests/snapshot.sh --mode capture --tag v1.0.0-8-gbcd96cd --overwrite --live
```

## Run reports

Set `E2E_REPORT_JSON` to write a machine-readable run report next to the console output:

```bash
SAASUS_E2E=true E2E_REPORT_JSON=artifacts/billing-e2e.json \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=E2E'
```

The document contains the run summary (story/step counts, method-coverage percentage,
duration in nanoseconds), per-story and per-step detail, per-method statistics, and the
list of untested calls. Variables and error messages are redacted.

Set `E2E_LOG_LEVEL=debug` for a structured execution trace: story and step boundaries,
validation outcomes, state updates, retries and the final coverage percentage.
