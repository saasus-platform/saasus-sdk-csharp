# Pricing API E2E tests

These tests reproduce the Pricing and metering lifecycle covered by the Go and
PHP SDK suites. They create a metering unit, fixed and tiered-usage pricing
units, a menu, a plan, and a tax rate; exercise updates and metering queries;
then remove all resources with the bulk initialization endpoint.

The lifecycle is executed with all four method styles generated by the C# SDK:
synchronous, synchronous `WithHttpInfo`, asynchronous, and asynchronous
`WithHttpInfo`. It covers 30 supported Pricing operations, or 120 generated
methods (including the expected 501 response from `UpdatePricingPlansUsed`).
Individual resource deletes are excluded because linked resources can make them
fail, Stripe-link operations require Billing/Stripe setup, and the generated
internal-error helper is outside the Pricing lifecycle.

Run the live E2E test with a dedicated SaaSus environment:

```bash
SAASUS_E2E=true \
SAASUS_SAAS_ID=... \
SAASUS_API_KEY=... \
SAASUS_SECRET_KEY=... \
TEST_TENANT_ID=... \
dotnet test tests/SaaSusSdk.Tests.csproj \
  --filter 'Category=E2E&FullyQualifiedName~Pricing'
```

`SAASUS_API_URL_BASE` can override the default API host. The test changes live
Pricing data, so use an isolated environment. The fixture test runs offline and
is included in the normal test suite.

## Snapshot tests

Capture a Pricing baseline:

```bash
SAASUS_E2E=true E2E_SNAPSHOT_MODE=capture E2E_SNAPSHOT_TAG=pricing-v1 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&FullyQualifiedName~Pricing'
```

Compare or report stored tags without calling the API:

```bash
E2E_SNAPSHOT_MODE=compare E2E_SNAPSHOT_COMPARISON_MODE=manual \
E2E_SNAPSHOT_OLD_TAG=pricing-v1 E2E_SNAPSHOT_NEW_TAG=pricing-v2 \
  dotnet test tests/SaaSusSdk.Tests.csproj --filter 'Category=Snapshot&FullyQualifiedName~Pricing'
```

Artifacts are written beneath `tests/E2E/Snapshots/pricing/` using the shared
Go/PHP-compatible snapshot layout. Set `E2E_SNAPSHOT_STORIES` to select a
subset, or use `E2E_SNAPSHOT_OVERWRITE=true` when intentionally replacing a
tag.

Snapshot step parameters are recorded as named objects (`pricing_unit_id`,
`body`, ...) so volatile values such as resource IDs and request-body identifier
lists are normalised to `[DYNAMIC]`. The Pricing collection endpoints do not
guarantee ordering, so a comparison ignores a pure re-ordering of the same
objects and compares raw bodies structurally.
